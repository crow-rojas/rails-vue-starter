# rails-vue-starter: agent guide

A starter for Rails apps with an Inertia + Vue frontend, PostgreSQL and Kamal, built to be developed mostly by coding agents. This file is an index: each rule points to the tool that enforces it.

## Commands

- `bin/setup`: install gems, packages and git hooks, write `.env` with free ports, start Postgres in Docker, prepare the databases and run the app. `--skip-server` stops before the dev server.
- `bin/dev`: run Rails and Vite on the `PORT` from `.env`.
- `bin/check`: the fast gate (lint, types, generated types, `bin/guard`, Rails tests), about 13 s. The Stop hook runs it after each turn.
- `bin/ci`: everything CI runs (`config/ci.rb`), about 40 s; `git push` runs it. **You are done only when it is green.**
- `bin/rails test`, `bin/rails test:system`: Minitest unit, integration and browser tests.
- `pnpm lint`, `pnpm format`, `pnpm check`: ESLint, Prettier and the Vue type check.
- `bin/merge <pr>`: merge a pull request whose checks are green, as a fast-forward of main that keeps its signed commits. Never use GitHub's merge buttons.

## Seeing your change

- `bin/dev` prints the URL. Sign in as `demo@example.com` with `demo-password-123` (development only; it can open the admin dashboards).
- To look at a page, call `take_screenshot` in a system test and read the PNG under `tmp/screenshots` (a failing system test saves one too).
- Errors are in `log/test.log`, `log/development.log` and `/admin/errors`.
- When a test fails intermittently, re-run it once with the `--seed` it printed before changing code, then fix the cause.

## Map

- `app/javascript/pages`: Inertia pages, one Vue component per controller action.
- `app/javascript/components/ui`: shadcn-vue primitives. `app/javascript/components`: app components.
- `app/javascript/types/serializers`, `app/javascript/routes`: generated by Typelizer from the serializers and routes. Never edit them by hand; `bin/ci` fails when they are stale.
- `app/serializers`: Alba resources that define every prop a page receives.
- `app/controllers/projects_controller.rb` and everything named `projects`: **the reference resource. Copy its shape for a new one** (ADR-005).
- `config/deploy.yml`, `.kamal/secrets`: Kamal deploy, configured from the environment (ADR-006). Production reads variables, never a credentials file.
- `app/views/pwa`, `PwaController`: the manifest, service worker and offline page (ADR-007). The worker only answers page loads; never let it cache Inertia responses.
- `.claude/`: the agent hooks and deny rules (ADR-002). `.codex/hooks.json` runs the same Stop hook in Codex.
- `docs/adr`: decisions. `docs/research/versions.md`: pinned versions and their sources.

## Rules

1. **English for everything in the repo**: code, docs, commits, PRs, logs and errors. Conversations with agents can be in any language.
2. **No literal user-facing copy** (ADR-004). It goes in `config/locales/en.yml` and `es.yml` together; Vue reads it with `useI18n()` and the full key, `t("ui.page.thing")`. `i18n-tasks health`, ESLint and RuboCop fail on a missing key, an unused key or literal copy. Dates and numbers format with the app's `locale` from `useI18n()`, never the browser's.
3. **Conventional Commits**, one concern each, with no AI co-author trailers (the `commit-msg` hook rejects both).
4. **Never silence a check.** No `rubocop:disable`, `eslint-disable`, `@ts-ignore` or `@ts-expect-error` (the linters reject them), no `--no-verify`, no new exclusions in `.rubocop.yml`, `eslint.config.js`, `pnpm-workspace.yaml` or `.database_consistency.yml`. Fix the cause.
5. **Never delete, skip or loosen a test to get green, and never edit a migration that is on main** (`bin/guard`). The same goes for the harness (`bin/guard`, `config/ci.rb`, `lefthook.yml`, `.claude/`, workflows, linter configs). The `Guard-Override:` trailer is for humans only.
6. **Write the failing test first** when fixing a bug, and run it to see it fail for the right reason.
7. **No N+1 queries** (prosopite fails the test) and **no unsafe migrations** (strong_migrations fails the migration).
8. **Security defaults stay on** (ADR-003): an endpoint that sends email or checks a secret calls `limit_attempts`; an inline script uses `javascript_tag nonce: true`; a new external origin is added to the content security policy on purpose, never by loosening it.
9. **One application shape** (ADR-005): rules in models, thin controllers, user records loaded through `Current.user`, props through serializers and generated types, links through `@/routes`. An operation, form object or query object needs the reason ADR-005 gives for it.
10. **pnpm only**, and new dependencies need a reason in `docs/research/versions.md` with an official source. Gems resolve with a 7-day cooldown and packages with a 1-day minimum age.
11. **If a rule gets in the way, propose an ADR.** Do not break it, weaken a check, or skip a hook.
