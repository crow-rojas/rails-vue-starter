# ADR-007: Progressive web app

- Status: accepted
- Date: 2026-10-21
- Deciders: owner

## Context

An app built from the template should install on a phone or desktop and fail gracefully offline, without each app writing the same boilerplate. Rails 8.1 generates a manifest and a service worker stub but leaves them off, and its `Rails::PwaController` skips our locale switching. The worker's real risk is Inertia: a worker that answers page loads or Inertia requests from a cache hides the asset version check (a 409 and a full reload), so users keep an old bundle after a deploy, and cached pages carry one user's props.

## Decision

- Installable, nothing more: a manifest with `id`, `start_url` and `scope` at `/`, `display: standalone`, a 192 and a 512 icon plus a separate maskable one (`public/icon-192.png`, `public/icon.png`, `public/icon-maskable.png`; replace all three with the app's artwork). Chrome needs no worker to install from its menu, but its install prompt still asks for one with a fetch handler.
- `PwaController` serves `/manifest.json`, `/service-worker.js` and `/offline` from the root, so the worker controls the whole app, with the user's language from `ApplicationController`. The manifest is rendered in the request's language, so one app keeps one `id`. Responses stay `private`, so Thruster never caches them and a deploy reaches clients at once; the worker never lives in `public/` (a one-year public cache) or under `/vite/` (scope limited to `/vite/`).
- The worker (`app/views/pwa/service_worker.js.erb`) only touches page loads: network first, and the cached `/offline` page when the network fails. A page load is any navigation, a native form post included; Inertia requests and assets are not, and pass through untouched; fingerprinted assets already have a one-year HTTP cache. Its cache is named after `RailsVite.digest`. No update prompt is needed, since nothing it caches goes stale.
- The offline page has no scripts (a cached page has no fresh CSP nonce) and no Vite assets, and its copy is under `ui.pwa.offline`.
- An Inertia visit is not a page load, so offline it would fail silently. `inertia.ts` listens for the `networkError` router event and, when `navigator.onLine` is false, reloads, which the worker answers with the offline page.
- No CSP change: `manifest-src` and `worker-src` fall back to `'self'`. The worker action skips Rails' cross-origin JavaScript check, as `Rails::PwaController` does, because it holds no user data.
- Sensors: `test/integration/pwa_test.rb` (manifest fields, icons on disk, language, worker, offline page) and `test/system/pwa_test.rb` (registration at `/`, the cached offline page, the reload on an offline visit). Chrome's network emulation does not reach the worker, so its offline fallback was verified by stopping the server.

## Alternatives not taken

- vite-plugin-pwa, Workbox or Serwist: they precache a build, which this app doesn't need. vite-plugin-pwa also needs a manual backend setup with open pnpm and SSR issues, and is mid-rewrite.
- `Rails::PwaController`: no locale switching. Rails main adds an offline action to it; revisit when that ships.
- `name_localized` in one manifest: only Chrome reads it.
- An in-page toast for offline visits: it would keep the user on the page, at the cost of copy and a component; the reload is three lines.

## Consequences

- An offline form submit loses what was typed, and an unreachable server while the device is online still fails silently.
- An edit to only the offline page reaches installed workers with the next frontend change, which renames the cache.

## Triggers that reopen this ADR

| Topic | Reopens when |
|---|---|
| Web Push | An app needs notifications: VAPID keys, the `web-push` gem, a subscriptions table and a permission flow. |
| Offline data | Users need to read or write without a connection; that means caching per-user data and conflict handling. |
| Install button | The browser's own install UI isn't found by users; add a `beforeinstallprompt` button and manifest `screenshots`. |
